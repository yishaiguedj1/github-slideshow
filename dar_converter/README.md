# ממיר דיווחי ווצאפ ל-DAR

ממיר את הדיווחים של קבוצת הווצאפ (סריקות, בדיקות, ליווים) לשורות בתבנית ה-DAR המדויקת, בלי Claude API.
הודעות שהקוד לא מבין נאספות לקובץ, ומפוענחות בסשן של Claude Code (על חשבון המנוי) או ידנית.

## מבנה

```
dar/
  parse.py        ייצוא ווצאפ -> הודעות (זמן, שולח, טקסט; רב-שורתי, מערכת, נערך, נמחק)
  extract.py      שורת הודעה -> אירועים (סריקה / בדיקה / ליווי / מחסן / כותרת שעה)
  normalize.py    שמות עבריים -> שמות באנגלית, אזורים ומיקומים (C1/C2 + המיקומים ב-reference), קידומות וטעויות
  build.py        אירועים -> שורות DAR (זוגות, רציפות C2+C1, ליווים, Assumed Post, Shift)
  validate.py     כפילויות, שעות חריגות, ערכים לא ברשימה, חורים בדיווח
  write.py        כתיבה לתבנית (openpyxl, שומר עיצוב/רשימות/נוסחאות) + קובץ בדיקה נפרד
  evaluate.py     השוואה לאקסל אמיתי, שורה-שורה ושדה-שדה, דוח פערים
  corrections.py  תיקונים + למידה (כינויים חדשים, דוגמאות רגרסיה)
  pipeline.py     הרצה על טווח תאריכים (מקבל רשימת הודעות - מוכן לחיבור WAHA בהמשך)
config/settings.yaml          כללי הזנה (שעות יום, D/E, רציפות אזורים, ספים)
config/reference.example.yaml פורמט רשימת השמות (שמות בדויים)
config/event.schema.json      הסכמה הקשיחה של אירוע (לתיקונים)
```

הנתונים הפרטיים יושבים ב-`../data/` (ב-.gitignore): `whatsapp_chat.txt`, תבנית/אקסל אמיתי
`DAR_August_2026.xlsx`, `reference.yaml` (שמות), `corrections.yaml` (תיקונים), ופלטים ב-`out/`.

## הרצה

```bash
cd dar_converter
pip install -r requirements-dev.txt
python -m dar convert --from 2026-08-01 --to 2026-08-31 --template ../data/DAR_2026-08.xlsx
python -m dar evaluate --days auto --actual ../data/DAR_2026-08.xlsx --report ../data/out/eval.xlsx
python -m dar pending --from 2026-08-01 --to 2026-08-31      # שורות שלא זוהו, עם הקשר
python -m dar sheets-plan --from 2026-08-01 --to 2026-08-05 --existing existing.json
python -m dar sheets-requests --plan plan.json --sheet-ids ids.json --out requests.json
python -m pytest -q
```

תבנית לכל חודש: הטווח חייב להיות בחודש של התבנית (`--template` לחודש אחר).
`evaluate --days auto` משווה רק את הימים שבהם המפקח הראשון ברשימה פותח את היום כ-Shift 1.
`sheets-plan` / `sheets-requests` מכינים כתיבה לעותק של הגיליון הרשמי בגוגל שייטס
(ערכים ל-A:G ו-K:L, צבע אדום והערות) - ההרצה עצמה דרך מחבר Google Sheets בסשן של Claude
(ראו `CLAUDE.md` בשורש הריפו).

## כללים עיקריים (נלמדו מהימים שהוזנו ידנית, ינואר-אוגוסט 2026)

- `39-42 X סרק Y בדק c2` -> Patrol של X + Material Search של Y (`Metal screening C2 : X - Declined to sit`).
- F = התחלה, G = סיום, D = F פחות דקה, E = F פחות 30 שניות. דקה בודדת ("44 בדיקה") -> 43-44.
  סריקה עם שעה אחת ("20 סריקה בc2") -> 20-23. כמה נבדקים בשורה אחת -> דקה אחרי דקה.
- C2 ו-C1 של אותו סבב (פער עד 3 דק') נרשמים ברצף.
- ליווי: שורה לכל אדם ומיקום; מסתיים ב"סיום ליווי", בבדיקת היציאה (גם באזור השני), או בהחלפה.
  "X חזר ל-c2" / "המשך ליווי X" אחרי בדיקת יציאה = ליווי חדש; "עוברים לליווי ב-C2" = הליווי
  הפתוח עובר מקום; "כניסה ויציאה X C1" ו-"ליווי ובדיקה לX" = ליווי + בדיקת יציאה; "לכולם" =
  כל הליווים הפתוחים.
- שם של מאבטח אחרי האזור ("... C1 דנה") הוא מי שבדק; "X בדק" אחרי הנבדק - X הבודק.
- שם משותף למאבטח ולמבקר שמלווה (למשל שני אנשים בשם זהה): בשורת ליווי - המבקר.
- טווח הפוך ("49-46", "42-25") מתוקן לפי משך סריקה סביר ומסומן בהערה.
- הודעה שנערכה: שעות עד 15 דקות אחרי זמן השליחה נשארות באותה שעה.
- Assumed Post: Shift 1 = המפקח (מפקח שני אחר הצהריים / מפקח מחליף - לפי הדיווחים);
  שאר העמדות לפי שעות הפעילות בצ'אט (07-13 / 13-19 / יום מלא) ו-`shift_priority`;
  ערב חג (`holidays`) -> עד 14:00.
- סריקת מחסן, אזעקות, הערות מנהלה ו-Night Owl - לא נכנסים.

## אין ניחושים

שדה לא ברור נשאר ריק, והשורה נצבעת באדום עם "⚠ דרוש תיקון" והערה בתא (עמודה C).
שורה שנכתבה לפי כלל מתועד (למשל אזור שהוסק מהסבב) מקבלת הערה בלבד, בלי צבע.
סבב שדווח בו רק אזור אחד מסומן באדום - האזור החסר לא מומצא (`infer_missing_zone: false`).
קובץ הבדיקה (`review_*.xlsx`) מרכז את כל השורות המסומנות עם ההודעה המקורית.
